01 · The problem

Good prompts kept getting lost, and nobody wrote them the same way.

A clear prompt gets a useful answer on the first try. A vague one makes the AI guess, and you spend the next hour fixing the guess.

I saw it in my own work first. A prompt that worked great one week was buried in a chat the next. I rewrote it from memory and got a weaker answer. Now picture a whole team doing that, every day.

02 · The shape

So I gave every prompt the same five parts.

Role, Task, Context, Constraints, Format. Think of it like putting on a play. The Role is the costume: a UX researcher, a copywriter, a kind editor. The Task is what that character does today. Those two are a must. Without them, the AI is standing on an empty stage.

Context, Constraints and Format are the props. They make the scene sharper, but the play works without them. The shape stops me writing wishes and gets me writing scenes.

03 · Version 1

Version 1 worked. It just lived in the wrong place.

I built the first library in Figma Make during Memorisely’s AI Design course. I even wrote the app itself as prompts in the same five-part shape: one for the screens, one for storing prompts in Supabase, one for an email sign-in.

Then I used it every day, and saw the catch. I don’t write prompts in a browser tab. I write them in Claude Code. Each time I needed one, I had to leave my work, find the site, copy and switch back. It only worked online, and it depended on two services I didn’t control.

04 · The rebuild

So I rebuilt it to come to me.

Prompts are just text. They don’t need a database. They need to be close by the moment I write.

I rebuilt it in Claude Code with one rule: all the prompts live in one file, and everything else reads from that file.

Architecture

One file feeds the app and the AI

The web page reads the prompts file. A small script turns the same file into Claude Code commands, like /ux-research. I edit once, and both stay in step.

Access

No database, so no login

Once the database was gone, there was nothing left to lock away. So the login went too. Nothing to sign up for, and no ties to Figma Make or Supabase.

Reach

It installs like an app and works offline

It sits in the Mac dock and on the phone’s home screen, and works without wifi. A prompt is most useful the moment you need it, connected or not.

05 · Built for everyone

No login wall, on purpose.

A login is the first wall a new designer meets on day one. A page that only works with a mouse is another. I took both walls away.

WCAG 2.2 AA

Works without a mouse

Every action works from the keyboard. Dialogs tell screen readers what they are, keep focus inside and close with Escape.

WCAG 2.2 AA

Easy to read, even in sunlight

Dark text on light backgrounds, well above the contrast rules. Tags put dark text on soft colours, so nothing fades away.

Equitable access

No sign-in, no tracking, works offline

No cookie banner and no analytics. Once installed, it works without wifi, so a new teammate, someone on a flight or anyone on a slow connection gets the same library.

06 · Looking back

No dashboards yet. Just a tool I reach for every day.

I’m still its main user, so it gets better wherever it gets in my way. Two small fixes I’m glad I made:

  • Required, in words. A red star became a “Required” tag. A screen reader says it, and it doesn’t depend on colour.
  • Thumb-first on the phone. The buttons used to run off the screen. Now Copy, the thing you came for, sits full width on top.
Lesson 01

Build where the work happens

Version 1 was a good app in the wrong place. The rebuild paid off the day the prompts showed up inside Claude Code.

Lesson 02

Match the tools to the content

Text never needed a database. Taking it out also took away the login and two services I didn’t control, and I lost nothing I used.

Lesson 03

A strict format pays off later

Every prompt has the same five parts. That’s why one small script could turn the whole library into Claude Code commands.

Next, I want a design team to use it for real. Then I’ll watch how fast people get a first useful answer, which prompts get copied and which ones nobody opens. That will decide what the library keeps.
