01 · what it does

What it does

The library groups prompts by intent, with personal notes on when each one works best — making AI a faster, more structured part of the design process. Categories include:

  • Research synthesis
  • Insight writing
  • Critique frameworks
  • Presentation prep
  • Surveys and interview scripts

It makes it much easier to find the right prompt when I need it and reuse what works.

"AI fluency isn't a vibe — it's a workflow you can show someone, a backend you can log into, and a list of things you choose not to ask the model." — the operating principle behind this tool
02 · how it's built

How it's built

The interface was built in Figma Make as a structured set of reusable cards, clear sections and a simple input pattern for adding new prompts. The early versions were prototype-only, but I wanted the library to behave like a real product — so the next step was to make it persistent and multi-user.

Going live with Supabase

To make the library actually usable, I connected it to Supabase as a lightweight backend. That gave me three things without writing a server:

  • A Postgres database for prompts, categories and notes — so additions persist between sessions instead of resetting on reload.
  • Email + password auth with row-level security, so the site is shareable but not fully open.
  • A small REST surface that Figma Make can call directly — no separate hosting, no glue code.

Picking Supabase was a deliberate trade-off — it kept the project well within a designer's reach (no DevOps, no auth from scratch) while still behaving like a proper deployed product.

The four places AI earns its keep in my week

The prompt library exists because I leaned hard on the same four moves and got tired of rewriting them. Each one shows up in the case studies — this is the consolidated version.

  • Synthesis — clustering raw research, support tickets and feedback-widget replies into themes. AI does the first pass; I verify against the source quotes.
  • Draft copy — tooltips, microcopy, education entries, OKR talking points. AI writes the first three variants in the right register; I pick and rewrite.
  • Translation between languages and audiences — Norwegian tax language into plain employee English, finance jargon into copy a CS team can hand a client.
  • Devil's advocate — paste a half-finished rationale into the chat and ask for the strongest objections a CFO or sceptical engineer would raise. Two out of three rounds are noise; the third catches a real hole.

What I don't ask AI to do: pick the IA, define the brand, or write the copy I'd put my name on without reading. The model is a fast pencil, not a designer.
