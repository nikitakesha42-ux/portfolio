01 · The problem

Everyone wrote prompts a different way. So I shaped one format the whole team could share.

Written clearly, the first answer from the AI assistant is useful. Written vaguely, it guesses, and you spend the next hour fixing a guess.

I noticed it in my own work first. A prompt that gave a great answer one week was lost in a chat history the next, so I rewrote it from memory, in a new shape, and got a weaker answer. When a whole team does the same, the waste multiplies.

02 · The shape

Role. Task. Context. Constraints. Format. Every prompt, every time.

Think of RTCCF as a little map for talking to the AI assistant. R is the Role: who it should be, like putting on a costume. A UX researcher. A copywriter. A kind editor. T is the Task: what that costume should actually do today. Those two are required, because without a who and a what, you’ve handed the assistant an empty stage. C, C and F (Context, Constraints, Format) are the props: they sharpen the scene when you add them, but a prompt stands on its own when the role and the task are strong. I use this framework because it stops me writing wishes and starts me writing scenes.

03 · Version 1

Version 1 worked. It just lived in the wrong place.

I built the first library in Figma Make while taking Memorisely’s AI Design and AI Coding course, using three prompts written in the same RTCCF shape the library stores. It had everything a library needs: five disciplines, search, tag filters, a detail view and one-tap copy. Supabase kept the prompts, and an email sign-in kept it to the team.

  • Prompt 1 · The whole app. Every screen and interaction, described as one RTCCF prompt.
  • Prompt 2 · Storage. Connect Supabase to create, read, update and delete prompts. Nothing more.
  • Prompt 3 · Sign-in. Basic authentication, so only the team could get in.

Using it every day showed me the gap. I don’t write prompts in a browser tab. I write them in Claude Code on my Mac, and sometimes on my phone. Each time I needed a prompt, I had to leave my work, open the site, copy and switch back. It only worked online, and the whole library depended on two platforms I didn’t control.

04 · The rebuild

So I rebuilt it as one web page that goes wherever I work.

33 prompts are just text. They don’t need a database. They need to be within reach the moment I write.

I rebuilt it in Claude Code in November with one rule: the prompts live in one file, and everything else reads from it.

Architecture

One file feeds the app and the AI assistant

All 33 prompts live in prompts.json. The web page reads it, and a small script turns the same file into five Claude Code skills: /ux-research, /writing, /design-systems, /prototyping and /design-engineering. I edit once, and both stay in step.

Reach

Installs like an app and works offline

It installs to the Mac dock and the phone’s home screen, and works without wifi once installed. A prompt is most useful the moment you need it, connected or not.

Access

No backend, so no account

Without a database, there was nothing left to guard with a login, so the login went too. Fewer moving parts, nothing to sign up for, and the library is no longer tied to Figma Make or Supabase.

Sync

Sync only when I ask for it

To keep my Mac and phone in step without bringing a server back, edits can sync through a private GitHub Gist. It’s opt-in, the key stays in my browser, and it saves a second after each change.

The result is one HTML page that goes anywhere a browser does: pinned to the Mac dock, on the phone’s home screen, and read directly by Claude Code when I design.

05 · Built for everyone

Accessibility and equity weren’t a checklist I did at the end. They shaped what the library became.

“No sign-in” isn’t a shortcut, it’s a choice. A login wall is the first barrier a new designer on day one, a teammate on their own laptop, or anyone using a screen reader runs into. The rest of the decisions below were made in the same spirit.

WCAG 2.2 AA

Keyboard-first and screen-reader friendly

Every action reachable without a mouse. Dialogs announce themselves to screen readers, trap keyboard focus, and close on Escape. Focus states visible on every control.

WCAG 2.2 AA

Contrast you can read in sunlight

Body text 20:1 and navy sidebar 16:1 (both AAA). Secondary labels meet AA. Tag chips put dark text on pastel to hold 4.5:1 even where the palette is soft.

Equitable access

No sign-in, no tracking, works offline

No consent banner, no analytics either. Once installed, it works without wifi, so a new teammate on day one, someone on a flight, or anyone on a slow connection sees the same 33 prompts.

06 · Keeping it alive

A library is only useful while it stays true. So keeping it up to date is part of the design.

There’s no admin panel. I edit a prompt in the app or straight in prompts.json, export, and commit. One command rebuilds the Claude Code skills from the same file. If my local edits drift, Reset from source brings the library back to the published version.

Daily use is also how it gets better. I’m its main user so far, so these changes came from noticing where it got in my way, not from a dashboard:

  • Required, in words. A red asterisk became a “Required” tag next to each required field. It reads the same to a screen reader and doesn’t rely on colour.
  • Room to write. Text boxes grow with what you type, so a long Context stays in view while you write it.
  • Thumb-first on the phone. The buttons in the prompt view used to run off the screen. Now Copy, the main action, sits full width on top, with Edit and Delete below.
  • Targets you can hit. Every control is at least 24 by 24 pixels, the WCAG 2.2 minimum, after an accessibility pass across my whole portfolio.
07 · Looking back

No dashboards yet. Just a tool I reach for every day, and three things I’d tell myself at the start.

Lesson 01

Build where the work happens

Version 1 was a good app in the wrong place. The rebuild earned its keep the day the prompts showed up inside Claude Code, where I actually write.

Lesson 02

Match the tools to the content

33 text prompts never needed a database. Taking it out also took away the login and the ties to two platforms, without losing anything I used.

Lesson 03

A strict format pays off later

Because every prompt has the same five slots, one small script could turn the whole library into Claude Code skills. The rule I set for writing prompts is what made the rebuild quick.

Next, I want a design team to use it for real. When they do, I’ll measure how long it takes to get a first useful answer, which prompts get copied most and which ones nobody opens, and let that decide what the library keeps.
