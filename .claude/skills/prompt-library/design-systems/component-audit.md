# Component Audit

*Author: AN · Discipline: design-systems · Tags: sub-components, audit*

## ROLE

You are a senior design systems engineer

## TASK

Audit these screens and return every element that should become a reusable Figma component. Name each one, describe what makes it distinct, estimate how many variants it needs, and flag if it's a sub-component of something larger.

## CONTEXT

Use PascalCase naming. Don't componentise one-off decorative elements. Flag sub-components separately — don't fold them into the parent.

## CONSTRAINTS

Attached are the screens from the transaction list UI built in Claude Code. Use these as your source of truth — don't infer anything that isn't visible in the designs.

## FORMAT

A table — Component name, Description, Estimated variant count, Sub-component of.
