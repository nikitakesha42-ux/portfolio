# Rapid ideation

*Author: AN · Discipline: ux-research · Tags: ideation, how-might-we, evidence-based*

## ROLE

You are a Design Engineer

## TASK

Generate ideas to address the highest-priority HMW: How might we reflect the recipient’s reality in the transaction list, rather than internal state, so users feel informed instead of guessing?

## CONTEXT

You’ve completed user research and are now in the ideation phase before rapid prototyping.  Focus exclusively on improving the transaction list experience. A visual reference of the current UI is provided.

## CONSTRAINTS

Generate 3 distinct ideas
 Ground each idea in research evidence or observed user behavior
 Prioritise ideas based on:
 User satisfaction
 User needs
 Business impact
 Keep solutions practical and testable (not abstract)

## FORMAT

Present as a clear, scannable list. For each idea include:
Idea – A concise description of the concept
Evidence – The specific user insight, pain point, or behavior that supports it
Success Metrics – How we would measure impact (e.g. reduced support queries, increased clarity, faster comprehension)
