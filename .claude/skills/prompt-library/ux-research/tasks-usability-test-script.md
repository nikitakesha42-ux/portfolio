# TASKS Usability Test Script

*Author: AN · Discipline: ux-research · Tags: usability-testing, tasks-framework, moderated-testing*

## ROLE

You are a UX researcher conducting usability testing for a  product, focused on the transaction list on the home dashboard.

## TASK

Create a structured usability test script using the TASKS framework (Task, Attempt, Struggle, Knowledge Gap, Success).
The script should help evaluate whether users can:
 Understand what is happening in their transactions at a glance
 Identify which transfers are complete or still in progress
 Recognise if any action is required
 Feel confident that everything is sorted without opening individual transactions

## CONTEXT

Users rely on the transaction list to understand what is happening with their money. However, the current experience only shows a static record (amount, recipient, status) and lacks clarity around:
 Whether transfers are complete or still in progress
 If any action is required
 Whether outcomes met expectations
 The exchange rate context behind decisions
This creates uncertainty, forces users to open individual transactions, and reduces trust and sense of control.

## CONSTRAINTS

Tasks must be scenario-based and realistic (not UI instructions)
 Avoid mentioning specific UI elements (e.g. “transaction list”)
 Do not guide or lead the user during tasks
 Include prompts for think-aloud behaviour
 Include light probing questions only after tasks
 Keep language simple, natural, and conversational
 Focus on observing behaviour, not opinions
 Limit to 3–4 high-quality tasks

## FORMAT

Structure the usability test script as follows:
1. Setup (1–2 prompts)
 Brief context
 Ask user to think out loud
2. Tasks (3–4 total)  For each task include:
Scenario (real-life situation)
Moderator note (what to observe: confusion, hesitation, clarity)
3. Reflection (3–4 questions)
 What’s happening here?
 Is everything clear?
 Would you do anything next?
 How confident do you feel?
4. Close (1 question)
 If you left this now, how would you feel about your transactions?
Output requirements
 Keep it short (15–20 min session)
 Use natural language
 Make it easy to run live
